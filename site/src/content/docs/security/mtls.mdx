## Overview

All agent-server communication uses mutual TLS (mTLS) with TLS 1.3 exclusively. Both the agent and server present certificates signed by the same CA.

## Certificate Chain

```
┌─────────────────────────┐
│   OSEye CA (Root)       │
│   ca.crt / ca.key       │
└───────────┬─────────────┘
            │ signs
    ┌───────┼───────┐
    ▼               ▼
┌────────┐    ┌────────┐
│ Server │    │ Agent  │
│ .crt   │    │ .crt   │
│ .key   │    │ .key   │
└────────┘    └────────┘
```

## Configuration

### Agent

```bash
sudo oseye-config set OSEYE_TLS_CERT=/etc/oseye/certs/agent.crt
sudo oseye-config set OSEYE_TLS_KEY=/etc/oseye/certs/agent.key
sudo oseye-config set OSEYE_TLS_CA=/etc/oseye/certs/ca.crt
```

### Server

```bash
OSEYE_TLS_CERT_FILE=/etc/oseye/certs/server.crt
OSEYE_TLS_KEY_FILE=/etc/oseye/certs/server.key
OSEYE_TLS_CA_CERT_FILE=/etc/oseye/certs/ca.crt
```

## TLS Requirements

| Parameter | Value |
|-----------|-------|
| Protocol | TLS 1.3 only |
| Key type | ECDSA P-256 or Ed25519 (recommended) |
| Cipher suites | TLS 1.3 default (AEAD only) |
| Cert validity | 1 year (recommended) |
| CA validity | 10 years |

## Certificate Generation

### Using the included script

```bash
./scripts/generate_certs.sh
```

This creates:
- `infra/certs/ca.crt` + `ca.key` — Certificate Authority
- `infra/certs/server.crt` + `server.key` — Server certificate
- `infra/certs/agent-dev.crt` + `agent-dev.key` — Dev agent certificate

### Manual generation

```bash
# CA
openssl ecparam -genkey -name prime256v1 | openssl ec -out ca.key
openssl req -new -x509 -key ca.key -out ca.crt -days 3650 -subj "/CN=OSEye CA"

# Server
openssl ecparam -genkey -name prime256v1 | openssl ec -out server.key
openssl req -new -key server.key -out server.csr -subj "/CN=oseye-server"
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt -days 365

# Agent
openssl ecparam -genkey -name prime256v1 | openssl ec -out agent.key
openssl req -new -key agent.key -out agent.csr -subj "/CN=agent-hostname"
openssl x509 -req -in agent.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out agent.crt -days 365
```

## Agent Revocation

Revoke an agent by deleting its registration:

```bash
curl -X DELETE https://server:8000/api/v1/agents/{cn} \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

The server maintains a revocation list. Revoked agents cannot reconnect even with valid certificates.

## Startup Behavior

- If TLS certificates are missing, the agent refuses to start (unless `OSEYE_GRPC_INSECURE_DEV=true` for development)
- If the CA certificate doesn't match, the connection is rejected
- Certificate expiry is logged as a warning 30 days before
