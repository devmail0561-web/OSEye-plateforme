## Roles

OSEye implements three roles with increasing privileges:

| Role | Description |
|------|-------------|
| `viewer` | Read-only access to events, alerts, incidents |
| `analyst` | Viewer + acknowledge alerts, manage incidents, create cases |
| `admin` | Full access: manage users, rules, plugins, agents, rollback actions |

## Permissions Matrix

| Action | Viewer | Analyst | Admin |
|--------|--------|---------|-------|
| View events | Y | Y | Y |
| View alerts | Y | Y | Y |
| Acknowledge alerts | — | Y | Y |
| Escalate to incident | — | Y | Y |
| Manage incidents | — | Y | Y |
| Create cases | — | Y | Y |
| Rollback responses | — | — | Y |
| Manage rules | — | — | Y |
| Upload plugins | — | — | Y |
| Manage agents | — | — | Y |
| Manage users | — | — | Y |
| Server settings | — | — | Y |

## User Management

### Create User (Admin)

```bash
curl -X POST https://server:8000/api/v1/users \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "username": "analyst1",
    "password": "secure-password",
    "role": "analyst",
    "email": "analyst@example.com"
  }'
```

### Update Role

```bash
curl -X PATCH https://server:8000/api/v1/users/{id} \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"role": "admin"}'
```

## JWT Authentication

- Tokens signed with RSA (RS256)
- Default expiry: 60 minutes
- Refresh token: 7 days
- Role embedded in JWT claims

```json
{
  "sub": "user-uuid",
  "username": "analyst1",
  "role": "analyst",
  "exp": 1723500000
}
```

## Dashboard UI

The dashboard conditionally renders admin pages based on the user's role. Analyst and viewer users see only their permitted sections in the sidebar.
