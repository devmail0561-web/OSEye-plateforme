## Overview

OSEye's Response Engine executes autonomous defensive actions when the Decision Engine determines a threat requires immediate response. All actions follow the **act-then-notify** principle with admin rollback.

## Action Types

### Block IP

Blocks a malicious IP address using the platform-native firewall API.

| Detail | Value |
|--------|-------|
| Linux | nftables (preferred) or iptables fallback |
| Windows | WFP (Windows Filtering Platform) — in development |
| macOS | pf / pfctl — in development |
| Scope | Per-agent (local firewall) |
| Duration | Configurable (default: 24h) |
| Rollback | Admin unblock via dashboard or API |

### Quarantine File

Moves a suspicious file to an isolated location with no-access permissions.

| Detail | Value |
|--------|-------|
| Linux | `/var/lib/oseye/quarantine/` · chmod 000 |
| Windows | `%ProgramData%\OSEye\quarantine\` · ACL deny-all — in development |
| macOS | `~/Library/Application Support/OSEye/quarantine/` · quarantine xattr — in development |
| Metadata | Original path, SHA256, timestamp preserved on all platforms |
| Rollback | Admin restore via dashboard or API |

### Kill Process

Terminates a malicious process and its children.

| Detail | Value |
|--------|-------|
| Linux | SIGKILL via syscall |
| Windows | TerminateProcess() — in development |
| macOS | SIGKILL / EndpointSecurity response — in development |
| Scope | Process + child processes |
| Deduplication | Same PID not killed twice within 60s |
| State | Recorded in state store (SQLite) |

## Decision Flow

```
Event → Rule/ML Detection → Alert
                              │
                    Decision Engine
                    (risk matrix)
                              │
                    ┌─────────┼─────────┐
                    ▼         ▼         ▼
              BLOCK_IP  QUARANTINE  KILL_PROC
                    │         │         │
                    ▼         ▼         ▼
              Response Engine (execute)
                              │
                    ┌─────────┼─────────┐
                    ▼         ▼         ▼
              State Store   Notify    Audit Log
              (dedup)       (admin)   (BLAKE3)
```

## Risk Matrix

The Decision Engine uses a risk matrix to determine response:

| Severity | Confidence High | Confidence Medium | Confidence Low |
|----------|----------------|-------------------|----------------|
| Critical | Auto-respond | Auto-respond | Alert only |
| High | Auto-respond | Alert + recommend | Alert only |
| Medium | Alert + recommend | Alert only | Log only |
| Low | Alert only | Log only | Log only |

## Admin Rollback

Every automated action can be rolled back by an admin:

```bash
# Via API
curl -X POST https://server:8000/api/v1/responses/{response_id}/rollback \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Or via the dashboard: Decisions → select action → Rollback button.

## Audit Trail

All decisions and responses are recorded in an immutable journal:
- BLAKE3 hash chain (tamper-evident)
- Decision rationale (rule/ML source, confidence, risk level)
- Action taken and timestamp
- Rollback events linked to original action
