CODE DE CONDUITE

Version : 1.0
Date : 2026-08-06
Portée : Projet OSEye — contributeurs, mainteneurs, utilisateurs

NOTRE ENGAGEMENT

Dans l’intérêt de favoriser un environnement ouvert et accueillant, nous, contributeurs et mainteneurs, nous engageons à faire de la participation au projet OSEye une expérience exempte de harcèlement pour tous, quels que soient :

  • L’âge
  • La taille corporelle
  • Le handicap visible ou invisible
  • L’origine ethnique
  • Les caractéristiques sexuelles
  • L’identité et l’expression de genre
  • Le niveau d’expérience
  • L’éducation
  • Le statut socio-économique
  • La nationalité
  • L’apparence personnelle
  • La race
  • La religion
  • L’identité et l’orientation sexuelle

NOS STANDARDS

Comportements attendus (FAIRE)

Les exemples de comportements qui contribuent à créer un environnement positif incluent :

  • RESPECT — Utiliser un langage accueillant et inclusif
  • EMPATHIE — Respecter les points de vue et expériences différents
  • CONSTRUCTIVITÉ — Accepter les critiques constructives avec grâce
  • PRIORITÉ À LA COMMUNAUTÉ — Se concentrer sur ce qui est le mieux pour la communauté
  • BIENVEILLANCE — Faire preuve de bienveillance et de courtoisie envers les autres membres
  • TRANSPARENCE — Documenter publiquement les décisions techniques majeures
  • INCLUSIVITÉ — Accueillir activement les nouveaux contributeurs, partager les connaissances
  • PROFESSIONNALISME — Séparer les désaccords techniques des attaques personnelles

Comportements inacceptables (NE PAS FAIRE)

Les exemples de comportements inacceptables incluent :

  • HARCÈLEMENT :
    • Commentaires offensants liés au genre, orientation sexuelle, race, religion, handicap
    • Intimidation délibérée, stalking, suivi physique ou en ligne
    • Attention sexuelle ou avances non désirées
    • Publication de contenus sexuellement explicites ou violents
  • TOXICITÉ :
    • Trolling, commentaires insultants ou désobligeants
    • Attaques personnelles ou politiques
    • Harcèlement public ou privé
    • Publication d’informations privées d’autrui sans permission (doxxing)
  • CONDUITE NON PROFESSIONNELLE :
    • Utilisation d’un langage ou d’images sexualisés dans les espaces publics du projet
    • Comportement qui pourrait raisonnablement être considéré comme inapproprié dans un cadre professionnel
    • Sabotage délibéré du travail d’autrui
    • Violation répétée des règles de contribution après avertissement
  • GATEKEEPING :
    • Décourager activement les nouveaux contributeurs
    • Rejeter des contributions pour des raisons non techniques (« ce n’est pas assez complexe », « tu n’es pas assez expérimenté »)
    • Exiger des standards impossibles ou arbitraires

RESPONSABILITÉS DES MAINTENEURS

Les mainteneurs du projet sont responsables de clarifier les standards de comportement acceptable et sont tenus de prendre des actions correctives appropriées et équitables en réponse à tout comportement inacceptable.

Les mainteneurs ont le droit et la responsabilité de :

  1. MODÉRER — Supprimer, éditer ou rejeter :
    • Commentaires, commits, code, modifications wiki
    • Issues, pull requests, et autres contributions
    • Qui ne sont pas alignés avec ce Code de Conduite
  2. BANNIR — Bannir temporairement ou définitivement tout contributeur pour des comportements jugés :
    • Inappropriés
    • Menaçants
    • Offensants
    • Nuisibles
  3. COMMUNIQUER — Expliquer publiquement (si approprié) les raisons des décisions de modération, pour maintenir la transparence.

PORTÉE

Ce Code de Conduite s’applique :

Espaces du projet

  • Dépôts GitHub : issues, pull requests, discussions, commentaires de code
  • Communication : Slack, Discord, forums, mailing lists
  • Événements : conférences, meetups, sprints de développement (virtuels ou physiques)
  • Documentation : wikis, docs, tutoriels

Représentation publique

Ce Code s’applique également lorsqu’un individu représente officiellement le projet dans un espace public :

  • Utilisation d’une adresse email officielle du projet
  • Publication via un compte de réseau social officiel
  • Action en tant que représentant désigné lors d’un événement

Exemple : si vous parlez d’OSEye lors d’une conférence en tant que contributeur principal, vous représentez le projet.

APPLICATION

Signalement

Les cas de comportement abusif, harcelant ou autrement inacceptable peuvent être signalés en contactant :

Email de sécurité : security@oseye.dev
Mainteneur principal : @virus-one (GitHub) ou virus-one@oseye.dev

Toutes les plaintes seront :

  1. EXAMINÉES — Investiguées rapidement et équitablement
  2. CONFIDENTIELLES — L’identité du plaignant sera protégée par défaut
  3. SUIVIES — Accusé de réception sous 48h, résolution sous 7 jours (selon gravité)

Processus d’investigation

  1. Réception : mainteneur reçoit le signalement
  2. Évaluation : vérification des faits (screenshots, logs, témoins)
  3. Consultation : si nécessaire, consultation avec d’autres mainteneurs (anonymisation du plaignant)
  4. Décision : sanction proportionnelle (voir ci-dessous)
  5. Communication : notification au plaignant et au contrevenant

Sanctions

Les mainteneurs suivront ces Lignes Directrices d’Impact Communautaire pour déterminer les conséquences :

1. CORRECTION (avertissement)

Impact communautaire : Usage de langage inapproprié ou autre comportement jugé non professionnel ou malvenu.

Conséquence : - Avertissement écrit privé, expliquant la nature de la violation - Demande d’excuses publiques (optionnel selon le cas) - Pas de conséquences durables si le comportement n’est pas répété

2. AVERTISSEMENT (suspension temporaire)

Impact communautaire : Violation via un incident unique ou série d’actions.

Conséquence : - Avertissement formel écrit - Suspension temporaire : - Aucune interaction avec la communauté pendant 7–30 jours - Interdiction de participer aux espaces publics (GitHub, Slack) - Violation de cette suspension → bannissement permanent

3. BANNISSEMENT TEMPORAIRE

Impact communautaire : Violation grave ou répétée des standards de la communauté.

Conséquence : - Bannissement de 3 mois minimum de toute interaction avec le projet - Aucune contribution (code, review, commentaires) - Aucune communication publique ou privée avec les membres - Violation → bannissement permanent

4. BANNISSEMENT PERMANENT

Impact communautaire : Démonstration d’un pattern de violation, harcèlement soutenu, agression envers des individus ou classes d’individus.

Conséquence : - Bannissement permanent de toute forme de participation publique au projet - Comptes GitHub bloqués - Accès révoqué à tous les canaux de communication - Non négociable : aucune procédure d’appel

RÉSOLUTION DES CONFLITS TECHNIQUES

Les désaccords techniques sont normaux et attendus. Ce Code ne s’applique PAS aux débats techniques légitimes.

Différence entre désaccord technique et toxicité

Désaccord technique (✅ OK) Toxicité (❌ Inacceptable)
“Je pense que cette approche est moins performante car X, Y, Z. Voici une alternative : …” “Cette approche est stupide. Tu ne connais rien à l’optimisation.”
“J’ai des doutes sur cette architecture. Avez-vous considéré les cas A et B ?” “Tu as visiblement jamais travaillé sur un vrai projet. C’est n’importe quoi.”
“Je ne suis pas d’accord avec cette décision. Documentons les deux options et votons.” “Si tu fais ça, je quitte le projet. C’est moi ou ton approche débile.”

Escalade technique (pas une violation du Code)

  1. Discussion dans la PR/Issue : arguments techniques, benchmarks, références
  2. Si blocage : escalade vers le lead (@virus-one)
  3. Décision finale : documentée dans docs/DECISIONS.md (ADR — Architecture Decision Record)

Les mainteneurs ne prendront PAS de sanctions pour des désaccords techniques exprimés de manière respectueuse.

MODIFICATION DU CODE DE CONDUITE

Ce Code de Conduite peut être modifié via pull request. Les changements nécessitent :

  1. Discussion publique : GitHub Discussion ouverte minimum 14 jours
  2. Approbation : 2/3 des mainteneurs
  3. Versioning : incrément de version (v1.1, v2.0, …)
  4. Notification : annonce dans tous les canaux du projet

ATTRIBUTION

Ce Code de Conduite est adapté du Contributor Covenant v2.1, avec ajouts spécifiques au projet OSEye.

Les Lignes Directrices d’Impact Communautaire s’inspirent de l’échelle de modération de Mozilla.

QUESTIONS FRÉQUENTES

Que faire si je suis témoin d’une violation ?

Contactez immédiatement un mainteneur via email (security@oseye.dev) ou message privé GitHub. Ne confrontez pas directement la personne si la situation est dangereuse.

Que faire si je suis accusé à tort ?

Le processus d’investigation vérifie les faits avant toute sanction. Si vous êtes contacté par un mainteneur, coopérez et fournissez votre version. Si vous pensez que la décision finale est injuste, vous pouvez faire appel en contactant deux autres mainteneurs (hors celui qui a traité le cas initial).

Les mainteneurs sont-ils eux aussi soumis à ce Code ?

Oui, absolument. Aucune exception. Les mainteneurs qui violent ce Code peuvent être retirés de leur rôle par vote des autres mainteneurs (majorité 2/3).

Puis-je signaler de manière anonyme ?

Oui. Utilisez un email temporaire ou contactez via un compte anonyme. Cependant, l’investigation peut être plus difficile sans possibilité de follow-up.

Que se passe-t-il si le contrevenant est le lead du projet (@virus-one) ?

Contactez directement les autres mainteneurs seniors. Si tous sont impliqués, contactez GitHub directement via leur Community Guidelines.

ENGAGEMENTS DES MAINTENEURS

En acceptant le rôle de mainteneur, je m’engage à :

  • ✅ Traiter tous les signalements avec sérieux et dans les délais annoncés
  • ✅ Respecter la confidentialité des plaignants
  • ✅ Appliquer les sanctions de manière cohérente et sans favoritisme
  • ✅ Documenter les décisions de manière transparente (hors informations sensibles)
  • ✅ Me récuser si je suis personnellement impliqué dans un conflit
  • ✅ Écouter les retours de la communauté sur l’application de ce Code
