# OSEye Agent — Guide CLI

Le package **`oseye-agent`** contient deux binaires complémentaires :

## 📦 Contenu du package

```
/usr/bin/oseye-agent       # Daemon de collecte (service systemd)
/usr/bin/oseye-config      # CLI d'administration
/usr/lib/systemd/system/oseye-agent.service
/etc/oseye/agent.env.example
/etc/oseye/certs/          # Certificats (créés par enrollment)
/var/lib/oseye/            # Buffer offline
```

---

## 🔧 `oseye-agent` — Daemon de collecte

**Rôle :** Processus long qui collecte et envoie les événements au serveur.

**Démarrage :** Géré par systemd (ne PAS lancer manuellement).

```bash
# Démarrer le service
sudo systemctl start oseye-agent

# Status
sudo systemctl status oseye-agent

# Logs temps réel
sudo journalctl -u oseye-agent -f

# Arrêter
sudo systemctl stop oseye-agent

# Redémarrer (après changement config)
sudo systemctl restart oseye-agent
```

**Mode debug (lancement direct) :**
```bash
# Lancer en foreground pour debug
sudo /usr/bin/oseye-agent

# Avec variables d'environnement
sudo OSEYE_LOG_LEVEL=debug /usr/bin/oseye-agent
```

**Caractéristiques :**
- Taille : ~9 MB
- Permissions : CAP_SYS_ADMIN, CAP_NET_ADMIN (pour eBPF)
- Collecteurs : eBPF, auditd, inotify, fanotify, journald, netlink, syslog
- gRPC client avec mTLS
- Buffer SQLite pour mode offline

## ⚙️ `oseye-config` — CLI d'administration

**Rôle :** Commandes ponctuelles pour enrollment, configuration, diagnostic.

### Enrollment

```bash
# Enrollment initial (obligatoire)
sudo oseye-config enroll \
  --server oseye.example.com:443 \
  --token 4d223dfc3b2347cfd3b833b69f83f7fa9ab9478678842707185d5fdfe05fa6dd \
  --grpc-port 50051

# Options avancées
sudo oseye-config enroll \
  --server oseye.example.com:443 \
  --token <TOKEN> \
  --grpc-port 50051 \
  --agent-id <UUID> \
  --certs-dir /etc/oseye/certs \
  --env-file /etc/oseye/agent.env
```

**Processus d'enrollment :**
1. Télécharge le certificat CA (TOFU via HTTPS)
2. Génère clé privée RSA-2048
3. Crée une CSR (Certificate Signing Request)
4. Soumet la CSR au serveur avec le token
5. Reçoit le certificat signé
6. Écrit `/etc/oseye/agent.env` avec toute la config
7. Active et démarre `oseye-agent.service`

### Configuration

```bash
# Afficher toute la configuration
sudo oseye-config show

# Lire une valeur spécifique
sudo oseye-config get OSEYE_GRPC_ADDR

# Modifier une valeur
sudo oseye-config set OSEYE_MAX_CPU_PCT=2.0
sudo oseye-config set OSEYE_BATCH_SIZE=2000

# Supprimer une clé
sudo oseye-config unset OSEYE_ENROLL_TOKEN

# Voir le chemin du fichier env
sudo oseye-config env-file
# /etc/oseye/agent.env
```

### Diagnostic

```bash
# Valider la configuration
sudo oseye-config validate

# Vérifier que tous les fichiers existent
sudo oseye-config check-files
# Vérifie : TLS cert, TLS key, CA cert, Ed25519 key, buffer dir, quarantine dir
```

**Caractéristiques :**
- Taille : ~5 MB
- Exécution : ponctuelle (run & exit)
- Modifications : écrit atomiquement dans `/etc/oseye/agent.env`
- Locking : utilise flock pour éviter les race conditions

## 📝 Format du fichier de configuration

`/etc/oseye/agent.env` — Variables d'environnement chargées par systemd.

Exemple après enrollment :
```bash
# Generated by oseye-config enroll on 2026-08-17T13:00:00Z
OSEYE_GRPC_ADDR=oseye.example.com:50051
OSEYE_TLS_CERT=/etc/oseye/certs/agent.crt
OSEYE_TLS_KEY=/etc/oseye/certs/agent.key
OSEYE_TLS_CA=/etc/oseye/certs/ca.crt
OSEYE_AGENT_ID=963614f6-773e-4c7f-aff8-5655dddea9e8
OSEYE_BUFFER_PATH=/var/lib/oseye/buffer.db
OSEYE_MAX_CPU_PCT=4.0
OSEYE_MAX_MEM_MB=256
OSEYE_BATCH_SIZE=1000
OSEYE_BATCH_TIMEOUT_MS=1000
OSEYE_FANOTIFY_PATHS=/etc/passwd,/etc/shadow,/root/.ssh
OSEYE_INOTIFY_WATCHES=[{"path":"/tmp","recursive":false,"mask":4095}]
```

## 🔑 Variables de configuration disponibles

| Variable | Type | Défaut | Description |
|----------|------|--------|-------------|
| `OSEYE_GRPC_ADDR` | `host:port` | `localhost:50051` | Adresse du serveur gRPC |
| `OSEYE_TLS_CERT` | path | `/etc/oseye/certs/agent.crt` | Certificat client mTLS |
| `OSEYE_TLS_KEY` | path | `/etc/oseye/certs/agent.key` | Clé privée client |
| `OSEYE_TLS_CA` | path | `/etc/oseye/certs/ca.crt` | CA root |
| `OSEYE_AGENT_ID` | UUID | auto | Identifiant unique de l'agent |
| `OSEYE_BUFFER_PATH` | path | `/var/lib/oseye/buffer.db` | SQLite buffer offline |
| `OSEYE_BATCH_SIZE` | int | `1000` | Événements par batch |
| `OSEYE_BATCH_TIMEOUT_MS` | int | `1000` | Flush timeout (ms) |
| `OSEYE_MAX_CPU_PCT` | float | `4.0` | Limite CPU % (0 = illimité) |
| `OSEYE_MAX_MEM_MB` | int | `256` | Limite mémoire (MB) |
| `OSEYE_FANOTIFY_PATHS` | CSV | `/etc/passwd,/etc/shadow` | Chemins surveillés |
| `OSEYE_INOTIFY_WATCHES` | JSON | `[{"path":"/tmp",...}]` | Watches inotify |
| `OSEYE_JOURNALD_PRIORITY` | string | `` | Filtre priorité (info, warning, err...) |
| `OSEYE_JOURNALD_UNITS` | CSV | `` | Units systemd à surveiller |
| `OSEYE_SYSLOG_ADDR` | `host:port` | `127.0.0.1:514` | Listener syslog |
| `OSEYE_QUARANTINE_DIR` | path | `/var/lib/oseye/quarantine` | Dir quarantaine malware |
| `OSEYE_ED25519_SIGNING_KEY` | path | `/etc/oseye/certs/agent.ed25519.key` | Signature événements |
| `OSEYE_INSECURE_KEY_PERMS` | bool | `false` | Démarrer même si la clé Ed25519 a des permissions > 0600. **Ne jamais utiliser en production.** |
| `OSEYE_ENROLL_URL` | URL | `` | URL enrollment (auto-enrollment) |
| `OSEYE_ENROLL_TOKEN` | string | `` | Token enrollment (auto-enrollment) |

## 🔒 Sécurité — Clé privée Ed25519

**Permissions clé privée :** La clé Ed25519 (`OSEYE_AGENT_KEY_PATH` / `OSEYE_ED25519_SIGNING_KEY`) doit avoir les permissions `0600`. L'agent refuse de démarrer si d'autres utilisateurs peuvent la lire (protection contre le vol de clé).

```bash
# Vérifier les permissions
ls -la /etc/oseye/certs/agent.ed25519.key
# Doit afficher : -rw------- root root ...

# Corriger si nécessaire
sudo chmod 0600 /etc/oseye/certs/agent.ed25519.key
```

En environnement de test uniquement, passer `OSEYE_INSECURE_KEY_PERMS=true` pour contourner cette vérification.

## ♻️ Résilience et reconnexion

L'agent maintient un **buffer SQLite local** pour absorber les interruptions réseau sans perte d'événements.

- **Buffer capé à 100 000 événements.** En cas de dépassement, les événements les plus anciens sont supprimés (éviction FIFO) pour laisser place aux nouveaux.
- **Replay automatique au reconnect :** à la reconnexion gRPC, les événements bufferisés pendant la déconnexion sont rejoués dans l'ordre FIFO avant de reprendre la collecte live.

Le chemin du buffer est configurable via `OSEYE_BUFFER_PATH` (défaut : `/var/lib/oseye/buffer.db`).

---

## ⚡ Watchdog CPU/RAM

L'agent mesure en continu sa consommation CPU et RAM. Quand la consommation dépasse le seuil du profil actif (`OSEYE_MAX_CPU_PCT`, `OSEYE_MAX_MEM_MB`), il réduit automatiquement le taux de collecte (`throttle_factor`).

Le serveur peut également envoyer un signal `SET_THROTTLE` si le lag du bus Redis dépasse le seuil de backpressure, forçant l'agent à ralentir côté émission.

Pour ajuster les limites :
```bash
sudo oseye-config set OSEYE_MAX_CPU_PCT=2.0
sudo oseye-config set OSEYE_MAX_MEM_MB=128
sudo systemctl restart oseye-agent
```

## 🛠️ Exemples d'usage courants

### Scénario 1 : Installation standard

```bash
# 1. Installer le package
sudo dpkg -i oseye-agent_0.2.0_amd64.deb

# 2. Enrollment
sudo oseye-config enroll \
  --server prod.oseye.local:443 \
  --token <TOKEN_FROM_ADMIN> \
  --grpc-port 50051

# 3. Vérifier que ça tourne
sudo systemctl status oseye-agent
sudo journalctl -u oseye-agent -f
```

### Scénario 2 : Ajuster les limites ressources

```bash
# Réduire l'impact sur serveur de prod
sudo oseye-config set OSEYE_MAX_CPU_PCT=2.0
sudo oseye-config set OSEYE_MAX_MEM_MB=128

# Redémarrer pour appliquer
sudo systemctl restart oseye-agent
```

### Scénario 3 : Ajouter des chemins surveillés

```bash
# Ajouter surveillance de /home/admin/.ssh
sudo oseye-config set OSEYE_FANOTIFY_PATHS=/etc/passwd,/etc/shadow,/root/.ssh,/home/admin/.ssh

# Vérifier
sudo oseye-config get OSEYE_FANOTIFY_PATHS

# Appliquer
sudo systemctl restart oseye-agent
```

### Scénario 4 : Debug problème de connexion

```bash
# Vérifier la config
sudo oseye-config show
sudo oseye-config validate

# Vérifier les certificats
sudo oseye-config check-files

# Tester en foreground
sudo systemctl stop oseye-agent
sudo OSEYE_LOG_LEVEL=debug /usr/bin/oseye-agent
# Ctrl+C pour arrêter
sudo systemctl start oseye-agent
```

### Scénario 5 : Re-enrollment (certificat expiré)

```bash
# Arrêter l'agent
sudo systemctl stop oseye-agent

# Supprimer anciens certificats
sudo rm -f /etc/oseye/certs/{agent.crt,agent.key,ca.crt}

# Re-enrollment avec nouveau token
sudo oseye-config enroll \
  --server prod.oseye.local:443 \
  --token <NEW_TOKEN> \
  --grpc-port 50051

# Le service redémarre automatiquement
```

## ❓ FAQ

### Pourquoi deux binaires au lieu d'un seul ?

**Séparation daemon/CLI** — bonne pratique pour :
- Sécurité : agent minimal, pas de code d'enrollment embarqué en permanence
- Taille : daemon optimisé, CLI avec toutes les commandes
- Clarté : systemd gère uniquement le daemon

Autres outils similaires :
- **OSQuery** : `osqueryd` (daemon) + `osqueryctl` (CLI)
- **Docker** : `dockerd` (daemon) + `docker` (CLI)
- **PostgreSQL** : `postgres` (serveur) + `psql` / `pg_ctl` (CLI)

### Puis-je utiliser oseye-agent sans oseye-config ?

❌ **Non**, les deux sont nécessaires :
- `oseye-config` fait l'enrollment initial (obligatoire)
- `oseye-agent` ne peut pas démarrer sans `/etc/oseye/agent.env`
- Le package installe toujours les deux ensemble

### Comment changer la config sans redémarrer ?

Impossible — l'agent lit `/etc/oseye/agent.env` au démarrage uniquement.

Workflow :
```bash
sudo oseye-config set KEY=VALUE
sudo systemctl restart oseye-agent
```

### L'enrollment peut-il se faire automatiquement ?

Oui, via **auto-enrollment** au premier démarrage :
```bash
# Définir avant le premier démarrage
sudo oseye-config set OSEYE_ENROLL_URL=https://oseye.example.com:443
sudo oseye-config set OSEYE_ENROLL_TOKEN=<TOKEN>

# Au démarrage, l'agent détecte l'absence de certificats et lance l'enrollment
sudo systemctl start oseye-agent
```

### Puis-je gérer la config sans sudo ?

❌ **Non**, root obligatoire pour :
- Écrire dans `/etc/oseye/`
- Accéder aux certificats (`chmod 600`)
- Contrôler le service systemd
- Permissions eBPF (CAP_SYS_ADMIN)
